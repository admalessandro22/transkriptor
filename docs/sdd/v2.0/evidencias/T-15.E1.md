# Evidência — T-15.E1: ID fixo da extensão e Origin fixado

- **Requisito:** SEC-15.E1.
- **Data:** 29/09/2026.
- **Base:** `a5bf978`.

## O que mudou

- **`extension/meet/manifest.json`:**
  - Ganha `key` (chave pública RSA 2048 de desenvolvimento). O ID fica fixo em qualquer máquina: `mkcfobdlgdaeplnklpfcioojjgjjoojo`.
  - A chave **privada foi descartada** ao gerar: uma extensão carregada da pasta não precisa dela, e a publicação usa a chave da loja.
- **`config.EXTENSAO_IDS_PERMITIDOS`:** o ID de desenvolvimento. Os IDs da Chrome Web Store e do Edge Add-ons entram quando o usuário publicar (DP-15-05).
- **`meet_bridge.origem_permitida`:** `chrome-extension://` só com ID **exato** da lista (antes, qualquer `[a-p]{16,32}`). Loopback HTTP continua valendo para ferramentas locais e testes.
- **`meet_bridge` (WebSocket):** com o pareador, o token estático legado (transição D2→D4) deixa de autenticar.

## RED → GREEN

- **`test_origem_extensao.py`:** 4 falhas (sem `key`, sem lista, outro ID aceito, token legado presente), depois **5/5**. O teste recalcula o ID pela regra do Chrome (SHA-256 da chave pública, 32 hex mapeados de 0-f para a-p).
- **Migração:** `test_meet_bridge_seguranca.py` tinha dois testes que fixavam "qualquer ID bem formado vale". Agora aceitam o ID permitido e recusam os outros.

| Comando | Resultado |
|---|---|
| `pytest tests/test_origem_extensao.py tests/test_meet_bridge_seguranca.py tests/test_limite_linhas.py` | **23/23** |

| `npx vitest run` | **89/89** |
| `npm run test:e2e -- meet-transport.spec.js` | **7/7** |

## Consequência para quem já usa

- **ID novo:** a extensão carregada da pasta passa a ter este ID. Quem a carregou antes precisa **recarregá-la** em `chrome://extensions` e parear de novo (a credencial antiga fica no `chrome.storage` do ID anterior).
- **Pareamento:** a T-15.E2 torna esse pareamento automático.
